# 業務支援の導入と検証

AIの作成・職務範囲・接続の割り当てはFourmix IntelligenceのStudioで行います。プラグインはAIを新規作成しません。社内向けAIとお客様向けAIは、それぞれの一覧から選びます。

## 社内向けの利用

1. 管理者が「設定 → Fourmix Intelligence」で許可する業務と投稿の種類を選びます。
2. 編集担当者が管理メニュー「Fourmix Intelligence」を開き、本人のFourmix Intelligenceアクセストークンで社内向けAI一覧を取得します。
3. AIを選び、依頼します。投稿・固定ページでは編集画面の「この内容についてAIに相談」から対象を渡せます。参照できる対象だけをサーバーで確認します。
4. 業務操作を選んでプレビューし、対象・入力内容を確認して実行します。公開・削除・注文状態変更を含む更新は確認なしで実行しません。

WordPress側の操作はログイン中の本人の権限で実行します。投稿単位の閲覧・編集・削除、投稿種類ごとの作成・公開権限も確認します。投稿者が他人の下書きを参照したり、公開権限を持たずに記事を公開したりすることはできません。

本人のトークンは入力欄から消し、サイト・本人・WordPressセッションに束縛して15分だけ暗号化保持します。ブラウザーの保存領域や公開ブロックには渡しません。編集担当者向けAbilities APIも同じ本人接続を使います。

社内向けAIは選択時に本人の設定へ保存します。画面再読込では有効な短期接続で一覧を再取得し、保存したAIが現在も許可されている場合だけ復元します。接続期限後は本人の再接続が必要です。お客様向けAIを新しく設定する場合もStudioの公開用一覧を確認し、社内向けAIや一覧にないAIへの変更を拒否します。AIの選択はWordPressの業務権限を付与しません。

WooCommerce業務にはサイト管理者の許可と、担当者の実際の商品・注文・顧客・クーポン権限が必要です。商品一覧と単体読取は商品ごとに閲覧権限を確認し、商品公開には公開権限を別途確認します。注文はWooCommerce標準の権限確認を使用し、導入済みの注文状態だけを受け付けます。顧客業務は既存の`customer`利用者のID・表示名の読取に限定し、店舗管理者やメール・住所を返しません。商品・注文のプレビュー後に対象が変わった場合は再確認が必要です。

AIがFourmix Intelligence側の接続ツールを使う場合は、その本人が利用できるAI・ワークスペース接続の権限が適用されます。WordPressへ署名付きで接続する実行主体は設定済みの接続ユーザーです。AIへ渡す画面コンテキストは認可根拠にはなりません。EC-CUBEと同様の自動アカウント連携はまだなく、本人のトークンによる接続が必要です。

## お客様向けの利用

設定画面でお客様向けStudio AIを選び、AIコンシェルジュ・サイト内検索・関連記事のネイティブブロックを置きます。商品提案・まとめ買い・カート確認はWooCommerce導入時だけ表示します。実行直前にもAIの区分を確認し、社内向けAIの匿名実行を拒否します。

構造化カードは現在の公開・閲覧可能・パスワードなしの投稿だけに絞り、タイトルとリンクをWordPressから取得します。商品の表示状態・価格・在庫・購入可否はWooCommerceの現在値を使います。会話と自動案内の保存領域はAIごとに分けます。

索引へ送る本文も同じ公開条件を確認します。公開範囲を外れた記事は削除をキューに登録し、送信直前にも本文を再確認します。同期完了まで索引の反映には遅れがあります。お客様向けAIには公開用の資料と職務範囲だけを割り当ててください。

予約については`WC_Bookings`の有無を検出するだけです。予約作成・変更・取消は未実装です。WordPress本体の能力として公開しません。WooCommerce以外のEC・業務プラグインも自動で対応済みとは扱いません。

## 署名付き接続と更新の記録

署名、有効期限、要求の再利用、ワークスペースと接続IDの束縛、設定済み実行ユーザーを確認します。本文が変わった要求に同じ重複防止キーを使うと拒否します。成功済みは保存結果を返し、処理中または結果不明は再実行しません。

プレビューと実行記録は`fmi_preview_*`、`fmi_execution_*`の非自動読み込みオプションとして保持します。プレビューは10分で無効になります。実行記録は結果不明の再実行防止に必要なため自動削除しません。監査フック`fourmix_intelligence_operation_audit`には操作名・担当者・状態を渡し、本文・トークンを含めません。

Fourmix IntelligenceのPHP側にも持続する更新記録が必要です。対応するマイグレーションを適用してから署名付き更新を使用してください。既存接続は実行ユーザーの選択と接続確認が必要になります。

通常の接続先はWordPressの安全なHTTPクライアントを使い、リダイレクトを許可しません。統合開発環境の`WP_DEBUG`と固定定数による`platform`・`localhost`・`127.0.0.1`のHTTP接続だけを別途許可します。設定画面の任意URLにはこの扱いを適用しません。

## ローカル検証

2026年10月1日、WordPress 7.1 / PHP 8.3の既存統合環境で確認しました。

- `tests/public-request-guard.php`: 同一サイト・プロキシ・利用制限の34チェック。
- `tests/execution-journal.php`: 成功・重複・内容変更・結果不明・接続分離・監査。
- `wp eval-file tests/native-integration.php`: 22項目。合成担当者・下書き、本人確認、権限拒否、変更検知、REST nonce、署名再送、別ワークスペースの拒否、公開AIと内容の分離、同期時の公開条件を検証。設定を復元し、作成したデータを削除します。AIのHTTP応答は検証内で置換し、モデルを呼びません。
- WordPress標準の管理画面をEdge / Playwrightで1280pxと390px幅で表示。下書きのプレビュー時に未更新、本人確認後に更新、REST APIで結果を再取得する一連の操作を確認。JavaScript例外なし。合成データと専用セッションを清掃し、設定を復元。

追加の`tests/studio-selection-integration.php`は既存WordPressの実REST・設定保存で10項目を確認しました。AIの選択保存・再取得、業務許可との対応、お客様向けAIの設定、社内AIへの公開設定変更の拒否、権限撤回と匿名拒否を含みます。Studio一覧だけを合成応答に置換しており、実トークンの権限と推論は未検証です。

既存WordPressサイトにはWooCommerceを導入していません。別途、WordPress.org公式11.1.2を独立した合成DB・一時コンテナへ導入し、商品・注文・顧客の実CRUDを含む27項目を従来方式とHPOS方式で実行しました。メールと外部HTTPは検証専用フックで停止し、決済・実際の公開は行っていません。その後、追加インストールの個別承認が必要との指示を受けたため、追加実行と清掃を停止しました。この記録は参考証拠として区別し、WooCommerceの正式な実機受入はインストール承認待ちです。検証用コンテナ・合成データの範囲を保持しています。

予約、実トークンによるAI一覧・推論、実際の公開・メール・決済は未検証です。公開ブロックの実モデルによる検索精度も未検証です。WooCommerceのクーポン作成・フロント購買表示も今回の実測範囲には含みません。

手動確認の入口は`http://localhost:48093/wp-admin/admin.php?page=fourmix-intelligence-operations`です。設定画面で業務を許可してから、合成の下書きでプレビュー・確認を試してください。
